# EPT 个人额度接入 · v0.4.0 · 2026-11-04

## 范围与前提

EPT 是 v0.4 默认个人额度来源，替代全部 FinOps 浏览器读取 / 登录流程。桌宠不需要 Edge / Chrome，不读取浏览器 profile、Cookie、localStorage 或报告页面，也不提供报告链接设置、浏览器登录或登出入口。Playwright 仅用于开发测试，`playwright-core` 不是生产运行依赖；Electron 自带 Chromium 只用于本地界面。

使用前必须在当前电脑自行安装 EPT，由本人按 EPT 自身流程登录，并确认 `ept usage` 正常。桌宠只调用独立的本机 `ept.exe` 进程：

- 不安装或附带 EPT 二进制，不携带密码，不代办 EPT 登录 / 登出。
- 不读取、复制或导入 EPT token / config；EPT 使用自己已有的凭据和登录状态。
- 不从企业浏览器会话或 DeepSeek Key 获取 EPT 认证，不绕过认证、MFA 或 TLS 校验。
- 不发模型推理请求，也不购买额度。

## 可执行文件定位

默认定位当前用户主目录中的 `.ept/bin/ept.exe` 和 `PATH` 中的 `ept.exe`。安装位置不同，可在桌宠设置中填写可选的绝对 `ept.exe` 路径；这是可执行文件位置，不是任意命令输入框，不要加入参数、引号包裹的命令串、token、config 路径或报告 URL。

PowerShell 中可先由本人检查 CLI：

    ept usage --help
    ept usage --summary-only --json

若 EPT 未加入 `PATH`，可用当前用户主目录的典型安装路径验证：

    & "$HOME/.ept/bin/ept.exe" usage --summary-only --json

路径不存在时请确认 EPT 实际安装位置，而不是创建假的额度文件或复制另一台机的凭据。桌宠升级或修改自定义路径不等于完成 EPT 登录。绝对路径换机后可能需要重设。

## 固定命令优先与严格回退

首选调用固定可执行文件和固定参数：

    ept usage --summary-only --json

2026-11-04 已在本机实测 `ept usage --help` 支持 `--json` 与 `--summary-only`，上述命令返回个人汇总 JSON，包含下列字段。本文只记录输出契约，不记录个人实时金额，不把实测值或历史截图用作默认额度。

| 字段 | 桌宠用途 |
| --- | --- |
| `plan_name` | 套餐名称；不据此推断金额 |
| `total_budget` | 个人总预算 |
| `actual_cost` | 个人总消耗，包含 LiWork 等使用，非 Coding 分项 |
| `usage_percentage` | 个人汇总用量百分比；数值已经是百分数，不再乘 100 |
| `reset_cycle` | 重置周期；不据此编造具体重置时间 |

剩余额度根据有效个人总预算与个人总消耗计算。显示时可以舍入，不先舍入输入再计算；字段缺失、不合法或无法确认个人汇总时应报错，不把未知值转换成零，也不猜测总额或供应商更新时间。

**回退条件只有一个：旧 CLI 明确返回 `unknown flag`。**此时才调用：

    ept usage

文本模式仍只解析完整且唯一的个人汇总，不把 Coding 分项、组织统计或多个条目自行累加成个人总消耗；个人总汇总须包含 LiWork 等实际使用。文本不完整或存在冲突时拒绝推测。

以下情况不触发文本回退：未登录、凭据过期、权限不足、网络 / VPN 问题、非 `unknown flag` 的命令错误、超时、输出超限、空结果或无效 JSON。不得因此切换浏览器、读取 token / config、复制其他人的登录状态或试探私有接口。

## 刷新、进程与缓存

- 默认 EPT 来源在启动时自动查询；悬浮卡 / 托盘可手动刷新，在线间隔可选 1 / 5 / 15 / 30 分钟。
- 进程使用 `shell: false`，Windows 隐藏 / 无控制台；参数固定，不经 shell 拼接执行用户输入。
- 每次子进程调用不超过 30 秒，进程输出上限为 1 MiB。超时 / 输出超限终止查询并显示失败，不无限等待或保存完整敏感输出。
- 切换来源、变更 EPT 路径或退出时取消旧代际任务；迟到的旧查询结果不得覆盖新来源 / 新配置，避免将旧账户数据显示成新账户。
- 查询失败保留当前来源的已有缓存并标「非实时」；从未成功查询、没有可用缓存时金额显示 `—`，不是零，不回填个人历史样例。
- 重启加载的缓存也不是实时数据。更换来源或 EPT 路径后，旧缓存不能作为新账户结果；成功查询时间是本地时间，不保证连续实时或供应商结算时效。
- 手动输入、文字识别与粘贴导入已删除。DeepSeek 仍使用独立 API Key 与余额语义，不套用 EPT 总预算 / 百分比。

## 故障处理

| 情况 | 本人可做的检查 | 桌宠行为边界 |
| --- | --- | --- |
| 找不到 `ept.exe` | 确认本机 EPT 安装、`PATH` 或设置中的绝对路径 | 不下载 EPT，不读取 config 查找凭据 |
| 未登录 / 凭据过期 | 按 EPT 自身流程登录，再确认 `ept usage` 正常 | 不提供密码输入，不代登录 / 登出 |
| 网络 / VPN / 权限失败 | 确认企业网络与本人权限，检查 CLI 本身能否查询 | 不绕过认证，不回退浏览器 |
| 明确 `unknown flag` | 检查 EPT 版本与帮助输出 | 仅此情况回退 `ept usage` 文本 |
| JSON / 文本无效或冲突 | 在本机核对个人汇总是否完整 | 报错，不把 Coding 分项当个人总额 |
| 超时 / 输出超限 | 检查 CLI 本身与环境，之后手动重试 | 终止本次调用，缓存标非实时 |
| 无 EPT 或暂时无法查询 | 排查 EPT 或选择自己的其他在线平台 | 未知值不伪造为零 |

排障时不要把原始命令输出、个人报告链接、token、config、密码、MFA 或 DeepSeek Key 发到聊天、仓库或共享日志。可以说明错误类别，先在本机核对是否包含敏感信息。

## v0.2 迁移与敏感历史数据

旧 `finops` 来源迁移为 `ept`，不再保存 `reportUrl` / `loginMode`，保留角色、尺寸等外观设置。旧浏览器来源与任何历史额度不作为新的实时 EPT 结果。

旧发布版 `user-data/dedicated-browser/`、旧内嵌会话及开发版 `.local-data/` 下的相应目录不会读取，也不会自动删除。这些历史文件可能仍包含 Cookie、令牌、报告链接或旧配置；“已停用 / 已迁移”不代表磁盘上的敏感信息已清理。

需要清理时，先完全退出桌宠，由本人确认目标路径后手动删除旧敏感目录。删除整个 `user-data/` 或 `.local-data/` 会同时丢失桌宠设置、额度缓存及本地加密 DeepSeek Key；不要在运行时清理，不要误删 EPT 自己的数据。桌宠不承担 EPT 登录状态的管理或注销。

`finops-integration.md`、`spec-chiikawa-v020.md` 与 `verification-v020.md` 仅为历史，浏览器入口、旧示例默认值及浏览器测试结论不适用于 v0.4。

## 跨机、分享与保留功能

目标 ZIP 为 `ChiikawaQuotaPet-0.4.0-Windows-x64-Personal.zip`，仅面向 Windows x64；使用完整目录，不只复制 exe。不附 EPT 二进制或凭据。另一台电脑的接收者必须已有 EPT 安装、本人登录且 `ept usage` 正常；不保证企业网络 / VPN / 权限可用，不承诺登录状态跨机可移植。

没有 EPT 时可选择 DeepSeek 或第三方通用在线接口；没有认证或有效接口时额度保持未知，不再提供手动来源。八个角色、110 / 165 / 235 三档尺寸、hover-only 独立额度卡、常显、拖动与托盘保留；DeepSeek 余额查询与本机加密 / 仅本次使用的 Key 选项保留，需接收者自己的 Key。

不要分享 `user-data/`、`.local-data/`、旧 browser profiles、个人报告链接、DeepSeek Key 或 EPT 凭据，也不要把运行过的完整目录直接转发。由打包脚本生成排除用户数据的分享包，仍不代表角色素材已获再分发授权。八张动画官网角色 PNG、粉丝 Wiki 非官方及 personal 不免版权的边界见 `THIRD-PARTY-NOTICES.md`。
